# Code quality review (2026-11-17)

Suggested order: 1 [DONE] -> 2+3 [DONE] -> 4+5 [DONE] -> 7+8 [DONE] -> 6 [DONE] -> 10+11 [DONE] -> 16 -> 9, 12-15.
Rename functions while an item touches them; item 16 is the final pass over the names that remain.

1. [DONE] Diagnostics/errors scattered. Fixed: new `diagnostics.py` holds `Severity` (StrEnum), a single frozen kw-only `Diagnostic` (severity, code, location, message, line, column), `Location`, `format_path`, `display_location`, `PlanningError(ValueError)` with a `diagnostics` tuple, and the `CourseValidationError`/`SchedulingError` subclasses. `ValidationIssue`, `ScheduleDiagnostic`, `.issues` and the scheduler's warning conversion were removed. The CLI catches `PlanningError` once and prints via `_print_diagnostic`; `SEVERITY_STYLES` is keyed by `Severity`. The Pydantic-specific `error_details()` helper stays in models and `DuplicateKeyError` stays private in loader. README, PHASE-1-PLAN and PHASE-2-PLAN are updated; the `display_location` test moved to `tests/test_diagnostics.py`.
   Original: ValidationIssue/CourseValidationError/display_location/_ENTRY_TAGS (loader), ScheduleDiagnostic/SchedulingError/_failure (scheduler), issue() (models), SEVERITY_STYLES (cli). Two near-identical diagnostic classes with duplicated __str__ path code; list vs tuple; scheduler converts one into the other.
2. [DONE] Session type names/rules were duplicated across `SessionType`, `SESSION_RULES`, discriminator tags, `ScheduledSource`, and three copied duration validators. `FixedSession` now owns duration validation once, with `minimum_minutes`/`splittable` class metadata on each variant; `Interactive` declares its flexible-session metadata. Removed `SessionRule`, `SESSION_RULES`, `validate_minimum_duration`, and `SessionType`; exported the typed `SessionEntry` union from `plannings_tool`.
3. [DONE] Simplified the schedule-entry discriminator: its outer callable now distinguishes break from session; the session union uses Pydantic's native `Field(discriminator="type")`. Missing/invalid entry tags no longer leak `entry_kind()` internals. Added nested-tag handling to `display_location()` and regenerated `course.schema.json` with the native session type discriminator mapping. Tests cover invalid/missing tags and existing model instances.
4. [DONE] Pattern errors leaked regexes for Duration, Nonblank, TrainerId, and Color. Native Pydantic pattern validation now has wrap validators that translate mismatch errors to field-specific `PydanticCustomError` messages; `WithJsonSchema` preserves the editor patterns. Duration keeps its string representation and pattern in generated JSON Schema. Wrap validators are used rather than `BeforeValidator` because they can translate native regex failures without reimplementing regex checks.
5. [DONE] Removed duplicate Python `re.fullmatch` checks from `StringValue._validate` and `Trainer.exact_pattern`. Pydantic's native Rust-regex validation now enforces the patterns (including trailing-newline rejection), while item 4's wrappers only translate mismatch errors.
6. [DONE] `Duration` is now `Annotated[int, BeforeValidator(parse_duration_minutes), WithJsonSchema(...)]`: YAML strings such as `1h 15m` are parsed once into whole elapsed minutes, matching how `ClockTime`/`CalendarDate` parse into `time`/`date`. Removed `StringValue`, the `Duration` str subclass and its re-parsing `.minutes` property; `Defaults` uses plain `15`/`45` minute defaults (the JSON Schema still advertises `"15m"`/`"45m"`), so there is no unvalidated `Duration("15m")` construction. The generated JSON Schema still exposes the string pattern, and invalid durations keep the `duration_syntax` message.
7. [DONE] Moved `check_missing_manual_breaks()` out of YAML `loader.py` into `validation.py`; both CLI and scheduler import validation there. Added `Day.available_minutes()` and reused it for warning thresholds and floating-day scheduling.
8. [DONE] Course/day time ordering now compares `time` objects directly; `Day.effective_start()` and `effective_end()` return `datetime.time` rather than the validation-only `ClockTime` alias. `minutes_since_midnight()` remains only where minute arithmetic is needed.
9. __init__ imports cli.main (Typer/Rich on library import); stale docstring. -> script plannings_tool.cli:main.
10. [DONE] Split day scheduling into `_allocate_durations()`, `_allocation_diagnostics()`, and `_build_scheduled_entries()` orchestrated by `_schedule_day()`. Removed the unreachable Interactive-duration `RuntimeError`, computed the UTC day start once before building entries, and converted each entry instant to local time once. Split elapsed-minute calculation into `_available_minutes()` and the offset check into `_reject_offset_transition()`, replacing its per-minute scan with an offset comparison.
11. [DONE] `ScheduledEntry` now stores its source plus scheduling-specific values only. Its `kind`, `title`, `session_type`, `break_kind`, and `trainer_ids` are derived properties, and the CLI renders those directly without a redundant row-title branch.
12. CLI: success messages bypass format; multiple Console(); tests import private _print_diagnostic. (SEVERITY_STYLES KeyError risk resolved by item 1.)
13. Diagnostic codes bare strings -> StrEnum for owned codes.
14. Tests: test_cli_schema mixes CLI/schema; scheduler CLI tests in test_scheduler -> test_cli.py/test_schema.py.
15. Ruff rules minimal (add UP, SIM, RUF, PT, RET); pyproject description stale.

16. [DONE] Renamed functions to describe their behavior. The single advisory rule is now `check_missing_manual_breaks()` throughout the public API, CLI, scheduler and README (no generic aggregator was needed). Scheduler names are `_localize_wall_time(..., location)`, `_scheduling_error()`, `_wall_clock_at()` and `_fixed_duration_minutes()`; `_entry_identity()` and `_aware_at_offset()` were removed, while `_make_scheduled_day()` and `_check_no_offset_transition()` were refactored in items 10-11. In models, `issue()` became `error_details()`, and validators are now `check_timezone`, `check_time_order`, `check_email`, `check_unique_trainers` and `check_schema_version`; already action-oriented `reject_null_fields` and `check_minimum_duration` remain. `schema_text()` became `render_schema()`.
